You are the `/revise` command that fixes UI implementations that don't match the Figma design by referencing the raw YAML file response.

## Trigger

This command runs when the user executes:
```
/revise <yaml-file-path> [--component <component-name>] [--fix-style]
```

## Input Arguments

Parse the user's command input:

1. **yaml-file-path** (required, first positional argument):
   - Path to the YAML file generated by `get_figma_context`
   - Format: `.salt-ui/figma/{fileId}/{nodeId}.yaml`
   - If not provided, use the most recent YAML file from `.salt-ui/figma/`

2. **--component** (optional):
   - Specific component name to revise
   - If not provided, revise all components from the YAML

3. **--fix-style** (optional flag):
   - Focus on fixing Tailwind/style mismatches only
   - Skip structural changes

## Workflow Steps

### Step 1: Locate and Validate YAML File

If `yaml-file-path` not provided:
```bash
# Find most recent YAML file
ls -t .salt-ui/figma/*/*.yaml 2>/dev/null | head -1
```

Validate the YAML file:
- Check if file exists
- Verify it contains valid YAML structure
- Check file size to determine reading strategy

### Step 2: Determine Reading Strategy

Check file size to decide reading approach:

```bash
# Get file size in bytes
FILE_SIZE=$(stat -f%z <yaml-file-path> 2>/dev/null || stat -c%s <yaml-file-path> 2>/dev/null)

# If file > 100KB, use chunked reading
if [ $FILE_SIZE -gt 102400 ]; then
  echo "Large file detected (${FILE_SIZE} bytes). Using chunked reading."
  USE_CHUNKED=true
else
  USE_CHUNKED=false
fi
```

**Reading strategies:**

**Small files (< 100KB):**
- Read entire file at once using `Read` tool
- Parse complete YAML structure
- Process all components in memory

**Large files (>= 100KB):**
- Use chunked reading with `Read` tool + `offset` + `limit`
- Read YAML section by section (e.g., 500 lines at a time)
- Process each chunk before reading next
- Track position between chunks

### Step 3: Read YAML File (Chunked if Large)

**For small files:**
```
Read the complete YAML file at <yaml-file-path>
```

**For large files, use chunked reading:**

```bash
# Read file in chunks of 500 lines
CHUNK_SIZE=500
TOTAL_LINES=$(wc -l < <yaml-file-path>)

for offset in $(seq 1 $CHUNK_SIZE $TOTAL_LINES); do
  # Read chunk
  Read <yaml-file-path> with offset=$offset limit=$CHUNK_SIZE

  # Process chunk
  - Extract component names in this chunk
  - Identify component boundaries
  - Build partial component structure

  # Track progress
  echo "Processed lines $offset to $((offset + CHUNK_SIZE - 1)) of $TOTAL_LINES"
done
```

**Chunked reading guidelines:**
- Start with `offset=1`, `limit=500`
- Increment offset by limit for each chunk
- Stop when chunk returns fewer lines than limit
- Reconstruct component hierarchy across chunks

### Step 4: Parse YAML Structure

Extract from YAML (chunked or complete):

For each component:
- Component name (with markers: `[COMP]`, `[STYL]`, or none)
- Tailwind classes in `tailwindcss:` array
- Component hierarchy in `children:` array
- Text content in `content_text:` fields
- Nested structure with proper indentation

Build component tree:
```
ComponentTree {
  name: string
  marker: "[COMP]" | "[STYL]" | none
  tailwind: string[]
  children: ComponentTree[]
  textContent: string
}
```

### Step 5: Detect Implemented Files

Find existing implementation files:

```bash
# For React/Next.js
find . -name "*.tsx" -o -name "*.jsx" | grep -E "(component|Component)"

# For Vue
find . -name "*.vue"

# For Svelte
find . -name "*.svelte"

# For Angular
find . -name "*.ts" | grep -v ".spec."

# Match against component names from YAML
```

Create mapping:
```
YAML Component → Implemented File
```

### Step 6: Compare Implementation vs YAML

For each component from YAML:

1. **Read the implemented file** (chunked if large)

2. **Extract current implementation details:**
   - Used Tailwind classes
   - Component structure
   - Props and state
   - Text content

3. **Compare with YAML specification:**

   Check mismatches in:
   - **Missing Tailwind classes**: Classes in YAML but not in code
   - **Extra Tailwind classes**: Classes in code but not in YAML
   - **Incorrect structure**: Component hierarchy doesn't match
   - **Missing text content**: Text from YAML not in code
   - **Wrong marker handling**:
     - `[COMP]` should be custom implementation
     - `[STYL]` should have custom Tailwind
     - No marker should use registry component as-is

4. **Generate diff report:**

```
Component: Button
Status: MISMATCH

Issues:
- Missing Tailwind: rounded-[40px], flex, items-center
- Extra Tailwind: bg-blue-500 (not in YAML)
- Text mismatch: YAML says "Sign In", code says "Submit"
- Marker issue: Component marked [STYL] but using registry without customization
```

### Step 7: Show Diff and Confirm

Present the comparison results to user:

```
Found X component(s) with mismatches:

Components to revise:
- Button (3 issues)
- InputEmail (2 issues)
- LoginForm (structure mismatch)

Total issues: 12

Show detailed diffs? (y/n)
```

Use `AskUserQuestion` for confirmation.

### Step 8: Revise Components (Chunked Processing)

For each component marked for revision:

**If component file is large (> 500 lines):**
1. Read file in chunks to understand structure
2. Identify section to revise (e.g., specific Tailwind class string)
3. Make targeted edits using `Edit` tool
4. Verify edit didn't break file structure

**If component file is small:**
1. Read entire file
2. Apply revisions using `Edit` or `Write` tool
3. Ensure all changes are applied

**Revision types:**

**Fix Tailwind classes:**
```typescript
// Before
className="bg-blue-500 text-white px-4 py-2"

// After (from YAML)
className="bg-red-500 text-white rounded-[40px] flex justify-center items-center"
```

**Fix component structure:**
```tsx
// Before (missing nested child)
<div>
  <Label>Email</Label>
  <Input />
</div>

// After (from YAML with proper hierarchy)
<div className="flex flex-col gap-[4px]">
  <Label>Email *</Label>
  <Input placeholder="something@mail.com" />
  <p className="text-sm">This is the supporting text</p>
</div>
```

**Fix text content:**
```tsx
// Before
<Button>Submit</Button>

// After (from YAML)
<Button>Sign In</Button>
```

**Apply [STYL] marker customization:**
For components marked `[STYL]`:
- Get base component from registry (if exists)
- Add custom Tailwind classes from YAML
- Wrap or extend registry component with custom styles

### Step 9: Verify Revisions

After revising each component:

1. **Check syntax validity:**
   - For `.tsx`/`.jsx`: Verify JSX tags are balanced
   - For `.vue`: Check script/template/style sections
   - For `.svelte`: Verify component structure

2. **Compare against YAML again:**
   - Re-read YAML (same chunked strategy)
   - Verify all Tailwind classes applied
   - Check text content matches
   - Validate component structure

3. **Report verification result:**
```
Component: Button ✓ REVISED
- All Tailwind classes from YAML applied
- Text content matches
- Structure verified
```

### Step 10: Show Final Summary

Display revision summary:

```
Revision complete!

Components revised: 5
Components skipped: 2
Components with issues: 0

Files modified:
- src/components/Button.tsx (12 changes)
- src/components/InputEmail.tsx (8 changes)
- src/components/LoginForm.tsx (structure updated)

Next steps:
- Review revised components
- Run tests: npm test
- Check design matches Figma
```

## Error Handling

If revision fails:
- Stop immediately
- Show clear error message with component name
- Offer rollback: "Restore original files? (y/n)"
- Provide specific error details

## Chunked Reading Implementation

**Reading large YAML files:**

```
# Example: Reading 2000-line YAML file in 500-line chunks

Read(file_path=".salt-ui/figma/xyz/123.yaml", offset=1, limit=500)
  → Lines 1-500 (Wrapper component, Banner start)

Read(file_path=".salt-ui/figma/xyz/123.yaml", offset=501, limit=500)
  → Lines 501-1000 (Banner end, Container start)

Read(file_path=".salt-ui/figma/xyz/123.yaml", offset=1001, limit=500)
  → Lines 1001-1500 (Container children)

Read(file_path=".salt-ui/figma/xyz/123.yaml", offset=1501, limit=500)
  → Lines 1501-2000 (remaining components)
```

**Processing strategy across chunks:**
1. Track open/close brackets for component boundaries
2. Maintain component tree state across chunks
3. Reconstruct full structure after all chunks read
4. Process comparisons after complete tree built

**Reading large implementation files:**

Same chunked approach for large source files:
- Read in 500-line chunks
- Identify sections needing revision
- Apply targeted edits
- Verify each chunk independently

## Configuration

Read settings from `.claude/implement.local.md` if it exists:
- `auto_fix`: Automatically apply fixes without confirmation
- `chunk_size`: Lines per chunk (default: 500)
- `max_file_size`: Threshold for chunked reading in KB (default: 100)
- `dry_run`: Show changes without applying

## Example Usage

```bash
# Revise all components from YAML
/revise .salt-ui/figma/4zD0kyv2x9ao27VSridvya/772-27196.yaml

# Revise specific component
/revise .salt-ui/figma/4zD0kyv2x9ao27VSridvya/772-27196.yaml --component Button

# Fix only Tailwind/style issues
/revise .salt-ui/figma/4zD0kyv2x9ao27VSridvya/772-27196.yaml --fix-style

# Auto-detect most recent YAML
/revise
```

## Tips

- Always check file size before reading
- Use chunked reading for files > 100KB
- Process components one at a time for large revisions
- Verify each revision before moving to next
- Keep backups of original files
- Use `--fix-style` for quick style-only updates
